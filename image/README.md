# Windows Server 2025 base image bake

This directory builds the pristine Windows Server 2025 evaluation qcow2 used by
the runtime container. Run the bake on a Linux x86-64 host with KVM; macOS
cannot produce the supported image.

## Prerequisites

- Linux with hardware virtualization enabled and readable/writable `/dev/kvm`
- Packer 1.14 or newer
- QEMU tools (`qemu-system-x86_64` and `qemu-img`)
- OVMF firmware, normally from the Ubuntu `ovmf` package
- `curl`, `sha256sum`, `7z` (`p7zip-full`), and enough free disk space for the
  ISOs and 64 GB image
- The runtime SSH key and Administrator password generated by
  `runtime/gen-keys.sh`

The template defaults to the Ubuntu 24.04 OVMF files
`/usr/share/OVMF/OVMF_CODE_4M.fd` and
`/usr/share/OVMF/OVMF_VARS_4M.fd`. Override `PKR_VAR_efi_firmware_code` and
`PKR_VAR_efi_firmware_vars` when the bake host uses different paths.

## Obtain the evaluation ISO

The 64-bit English Windows Server 2025 evaluation ISO comes from the
[Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025).
The evaluation ISO provides the same `Windows Server 2025 SERVERSTANDARD`
edition name used by the answer file. To verify an unfamiliar ISO, mount it and
run:

```powershell
dism /Get-WimInfo /WimFile:D:\sources\install.wim
```

`build.sh` keeps both the Windows ISO and the virtio-win ISO in a local cache
directory (`ISO_CACHE_DIR`, default `image/.packer-cache`) and hands Packer
file paths, so the ISOs are only ever downloaded once. Two ways to supply the
Windows ISO:

- Set `ISO_URL` to the Evaluation Center download link. On the first run
  `build.sh` downloads it to `$ISO_CACHE_DIR/windows-server-2025.iso`.
- Or set `ISO_PATH` to an ISO you already have (or copy one to the default
  cache path).

If `ISO_CHECKSUM` (`sha256:<digest>`) is set the local file is verified
against it; otherwise the checksum is computed from the local file and only
used to satisfy Packer's own verification.

## Build

Generate the runtime key first, then run the wrapper from this directory:

```bash
../runtime/gen-keys.sh
export ISO_URL='https://go.microsoft.com/fwlink/?linkid=...'   # first run only
./build.sh
```

or with a pre-downloaded ISO:

```bash
ISO_PATH=/absolute/path/to/Windows_Server_2025.iso ./build.sh
```

`IMAGE_VERSION` defaults to the current UTC/local host date in `YYYYMMDD`
form. Set it explicitly for reproducible automation. The generated
`runtime/keys/administrator_password` is used for unattended setup, Packer
WinRM, and runtime WinRM. `ADMIN_PASSWORD` or `ADMIN_PASSWORD_FILE` can override
it. Optional resource overrides use standard Packer variables, for example:

```bash
IMAGE_VERSION=20260911 \
PKR_VAR_cpus=8 \
PKR_VAR_memory=16384 \
./build.sh
```

The first build downloads the current stable virtio-win ISO into the same
cache directory. Set `VIRTIO_WIN_ISO_PATH` to use a pre-downloaded ISO.
`build.sh` extracts only the Server 2025 `vioscsi`, `viostor`, and `NetKVM`
packages plus `virtio-win-guest-tools.exe`. Packer puts the drivers in a
root-level `$WinPEDriver$` directory on its generated `PROVISION` CD. Windows
Setup automatically scans that directory recursively before disk
configuration, without answer-file paths or CD drive letters.

Packer typically takes 30 to 90 minutes, depending on host and network speed.
The result is `dist/win-base-<version>.qcow2` plus a sha256sum-compatible
`.sha256` file.

## Debugging

Ask Packer to stop at a failed step:

```bash
./build.sh -on-error=ask
```

To inspect the installer over VNC, make the builder non-headless:

```bash
PKR_VAR_headless=false ./build.sh -on-error=ask
```

Packer prints the VNC endpoint in its logs. If Windows Setup cannot see the
target disk, press Shift+F10 and confirm that the `PROVISION` CD contains
`$WinPEDriver$\vioscsi\2k25\amd64`,
`$WinPEDriver$\viostor\2k25\amd64`, and
`$WinPEDriver$\NetKVM\2k25\amd64`. The CD drive letter itself is intentionally
not hard-coded.
